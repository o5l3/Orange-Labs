이번 릴리즈에서는 블루스크린 증상과 증적 파일이 올라오지 않던 문제를 주로 고쳤습니다. 네트워크 구역 화면은 노드를 구역에 배치하는 화면으로 바뀌었습니다. 에이전트 화면의 부하 탭에서는 이 PC 의 시스템 사용량과 CPU·메모리·디스크 대기를 바로 볼 수 있습니다.

> **업데이트 직후 예전과 달라 보이는 것이 두 가지 있습니다.** 노드 › 네트워크 구역의 탭이 「구역 요약」과 「노드 목록」 두 개로 바뀝니다. 파일함이 설정에서 빠지고 위쪽 메뉴에 「파일」이 생깁니다. 모두 의도한 변경이며 기능 이상이 아닙니다.

## 신규 · 에이전트 화면 부하 탭 위쪽에 시스템 사용량과 CPU·메모리·디스크 대기 게이지 추가

에이전트 화면 › 부하에서 이 PC 가 지금 자원을 얼마나 쓰고 있는지 볼 때 씁니다.

- **에이전트** — 부하 탭 맨 위에 「시스템 사용량」 막대와 큰 숫자, 그리고 「CPU 대기」·「메모리(페이지)」·「디스크 대기」 원형 게이지 세 개가 나옵니다. 그 숫자를 무엇으로 계산했는지와 부팅 시각도 함께 나옵니다.
- **에이전트** — 전에는 프로그램 목록만 있어서 PC 전체 사용량은 보이지 않았습니다. 프로그램별 TOP 10 은 별도 창으로 옮겼고, 그 창을 열 때만 조회합니다.

## 신규 · 설정 › 시스템 › 에이전트 설정에 증적 전송 속도 상한 칸 추가

증상의 증적 파일이 올라오면서 사내 회선을 많이 차지할 때 씁니다.

- **서버** — 설정 › 시스템 › 에이전트 설정의 「업로드/다운로드 속도 상한 (Mbps)」에 0 부터 1000 사이의 값을 넣습니다. 0 을 넣으면 제한하지 않습니다. 저장한 적이 없으면 에이전트 기본값인 4 가 보입니다.
- **서버** — 이 값은 증적 업로드와 에이전트의 파일 내려받기에 함께 적용됩니다. 범위를 벗어난 값은 0 또는 1000 으로 맞춰 저장합니다.

## 신규 · 노드 › 네트워크 구역 화면을 노드 배치·추천 구역 화면으로 교체

노드 › 네트워크 구역에서 어느 노드에 무엇을 해야 하는지 알기 어려울 때 씁니다.

- **매니저** — 「구역 요약」에서 구역마다 노드가 몇 대인지와 아직 배치되지 않은 노드를 봅니다. 「노드 목록」에서 노드를 골라 구역에 배치합니다. 배치되지 않은 노드에는 IP 대역·출구 IP·게이트웨이를 보고 고른 추천 구역이 나옵니다. 배치한 노드가 다른 곳에서 접속하면 「구역 밖 접속」으로 표시합니다.
- **매니저** — 구역이 하나도 없으면 서버가 묶어 둔 구역 후보에서 시작합니다. 구역을 저장하거나 게이트웨이를 추가하면 추천 구역을 다시 계산합니다. 예전 화면의 주소로 열면 노드 목록이 예전 화면에 가장 가까운 필터를 건 상태로 열립니다. 대시보드에 둔 네트워크 구역 위젯도 새 화면으로 바뀝니다.

## 개선 · 파일함을 설정에서 위쪽 메뉴 「파일」로 이동

파일함에서 규칙 파일이나 에이전트 파일을 다룰 때 씁니다.

- **매니저** — 위쪽 메뉴의 「파일」을 누르면 바로 파일함이 열립니다. 업로드 상한 같은 설정값은 설정 › 시스템 › 파일 설정 탭에서 바꿉니다.
- **매니저** — 전에는 설정 › 기록 › 파일함에 있었습니다. 파일 작업이 실패하면 서버가 보낸 사유를 그대로 보여 줍니다.
- **서버** — 내 폴더 맨 위에 「배포 파일」 폴더가 새로 생깁니다. 이 폴더는 지우거나 옮기거나 이름을 바꿀 수 없습니다.

## 개선 · 에이전트 화면 증상 탭에서 증상을 종류별로 묶고 원인 프로그램별 실행 흐름으로 표시

에이전트 화면 › 증상에서 어떤 증상이 무엇 때문에 났는지 파악하기 어려울 때 씁니다.

- **에이전트** — 증상을 시스템·에이전트·네트워크·이벤트·하드웨어로 묶어 보여 줍니다. 프로세스 증상은 원인 프로그램마다 실행 흐름과 증상 화살표로 그립니다. 예전 목록은 「세부 증상 보기」에서 그대로 볼 수 있습니다.
- **에이전트** — svchost.exe 증상 카드에는 어느 서비스에서 난 증상인지 서비스 이름을 함께 표시합니다. 증상 상세의 「분석」 탭은 덤프 분석기와 같은 화면을 씁니다. 그래서 같은 덤프를 두 화면에서 서로 다른 형식으로 보지 않아도 됩니다.

## 개선 · 블루스크린 증상이 올라오지 않거나 증상 상세에 원인이 비어 있던 문제

블루스크린이 난 PC 인데 증상 › 증상 목록에 블루스크린이 없거나, 증상 상세 › 분석에 원인이 나오지 않을 때 씁니다.

- **에이전트** — 크래시 당시 프로세스의 경로를 찾지 못해도 증상을 만듭니다. 블루스크린 룰은 중지 코드만 보고 판정합니다. 덤프를 만든 PC 와 Windows 빌드가 달라도 전체 메모리 덤프를 끝까지 분석해 원인 모듈까지 보여 줍니다.
- **에이전트** — 블루스크린 뒤 재부팅하면 Windows 가 덤프를 다 쓰기 전에 에이전트가 먼저 읽어서, 원인이 비거나 틀리게 나올 수 있었습니다. 이제 덤프를 다 쓸 때까지 최대 5분 기다립니다. 룰에 맞지 않는 덤프를 부팅할 때마다 다시 분석하던 것도 한 번만 분석하도록 고쳤습니다. 그래서 다시 분석하는 동안 PC 가 느려지던 일이 없어집니다. 31GB 전체 메모리 덤프를 분석하는 데 약 20초가 걸렸습니다.
- **룰** — 예전 분석기는 커널 덤프의 크래시 프로세스를 늘 System 으로 넘겼고, 블루스크린 룰 209개가 그 값을 조건으로 두고 있었습니다. 새 분석기가 실제 프로세스를 넘기자 System 이 아닌 블루스크린은 어느 룰에도 맞지 않았습니다. 증상을 묶는 기준은 바꾸지 않았으므로 새 증상은 기존 증상 줄에 이어집니다.

## 개선 · 증상 상세에서 증적 파일이 올라오지 않거나 붙지 않던 문제

증상 상세에서 증적 파일을 열려는데 첨부가 없다고 나올 때 씁니다.

- **서버** — 설정 › 시스템 › 에이전트 설정에서 정한 업로드 용량 상한·조각 크기·전송 속도 상한이 에이전트에 그대로 전달됩니다. 작은 증적 파일도 증상에 붙습니다. 아직 올라오는 중이면 「보내는 중 (받은 크기 / 전체 크기)」을, 끝내 올라오지 못했으면 「증적 없음」과 그 사유(크기 초과·압축 실패·보관 한도 초과 등)를 보여 줍니다.
- **서버** — 노드가 접속할 때 서버가 내려보내는 설정에 이 세 값이 빠져 있어서, 에이전트는 자체 기본값을 썼습니다. 그래서 1.6.242.0915 와 1.6.242.1006 에 안내한 상한 조정이 실제로는 적용되지 않았습니다. 상한을 올려 두신 서버에서는 업데이트한 뒤부터 전보다 큰 증적 파일이 올라옵니다. 한 번에 다 올라간 작은 파일만 증상에 연결되지 않던 문제도 함께 고쳤습니다.
- **매니저** — 이 표시는 증상 상세 타임라인과 프로세스 상세의 증상 탭에 똑같이 나옵니다. 전송이 끝난 증적은 지금처럼 내려받기 줄로 나옵니다.

## 개선 · 원격 제어에서 한글 입력이 제대로 되지 않던 문제

노드 상세 › 원격 제어로 접속해 한글을 입력할 때 씁니다.

- **매니저** — 한글을 입력하고 스페이스를 누르면 띄어쓰기가 그대로 들어갑니다. LG 그램·맥북처럼 물리 한/영 키가 없는 노트북에서도 한/영 전환이 됩니다.
- **매니저** — 전에는 띄어쓰기가 빠지고, 이어서 친 글자가 조합창 위치에 입력됐습니다. 이 수정은 노드에서 따로 고치거나 다시 배포하지 않아도 적용됩니다.
- **에이전트** — 키보드의 스캔코드 대신 한/영 가상 키를 넣도록 바꿨습니다.

## 개선 · 명령 관리에서 결과가 큰 1:N 명령이 끝나지 않은 채 남던 문제

명령 관리에서 결과가 큰 명령을 보냈는데 응답이 오지 않고 명령이 끝나지 않을 때 씁니다.

- **에이전트** — 한도를 넘는 응답은 보내지 않고 작은 실패 응답(-24)을 대신 보냅니다. 명령이 실패로 끝나므로 무엇이 잘못됐는지 알 수 있습니다.
- **에이전트** — 전에는 응답이 MQTT 전송 한도를 넘으면 중간에 버려졌습니다.
- **서버** — 이 실패는 다시 보내도 결과가 같으므로, 서버는 재시도하지 않는 실패로 판정합니다.

## 개선 · 느린 회선에서 에이전트 업데이트가 끝나지 않던 문제

회선이 느리거나 불안정한 사업장에서 에이전트 업데이트가 끝나지 않을 때 씁니다.

- **에이전트** — 내려받기가 중간에 끊기면 처음부터 다시 받지 않고 끊긴 지점부터 이어받습니다. 내려받는 중에 다음 확인 주기가 돌아오면 그 확인은 건너뜁니다.
- **에이전트** — 전에는 끊길 때마다 처음부터 다시 받아서 업데이트가 끝나지 않았습니다. 받는 도중 확인 주기가 돌아오면 같은 파일을 한 번 더 받았고, 회선이 느릴수록 이런 중복 내려받기가 자주 생겼습니다.

## 개선 · 정팀장이 느린 PC 의 원인을 CPU 만 보고 판단하던 문제

노드 정보 › 정팀장에 「느려요」 같은 질문을 할 때 씁니다.

- **정팀장** — CPU 뿐 아니라 메모리 사용량·디스크 I/O·핸들 상위 프로세스까지 함께 보고 원인을 찾습니다. 디스크는 디스크 지연이 높을 때만 원인으로 봅니다.
- **정팀장** — 전에는 CPU 를 적게 쓰는 원인은 놓쳤습니다. 또 전송량 값에 네트워크 전송량이 섞여 있어서, 네트워크를 많이 쓴 경우에도 디스크를 원인으로 지목했습니다.

## 개선 · 증상 상세에서 정팀장이 그 증상의 기록을 근거로 답변

증상 상세 › 정팀장에서 그 증상에 대해 물을 때 씁니다.

- **룰** — 그 증상이 언제·몇 번·어느 프로세스에서 났는지를 근거로 답합니다. 답에 나오는 증상 시각은 한국 시각으로 적습니다.
- **룰** — 강제종료·핸들과다점유·TCP·CPU점유·COM응답 증상의 설명에 「이 기록을 읽는 법」을 더했습니다. 예를 들어 TCP 증상은 PC 전체 누적 성공률이 50% 아래일 때만 기록되므로, 횟수가 곧 실패 빈도는 아닙니다. 이 설명은 증상 상세의 「설명」에도 그대로 나옵니다.

## 개선 · 정팀장이 맞게 조사하고도 「판단을 마치지 못했습니다」로 끝나던 문제

노드 정보 › 정팀장이나 증상 상세 › 정팀장에서 조사는 했는데 결론이 조사 결과와 다르게 바뀌거나 한 줄로 끝날 때 씁니다.

- **정팀장** — 조사한 결과대로 결론을 내고 끝냅니다.
- **정팀장** — 뜻이 분명한 질문에는 되묻지 않고 바로 조사해 답합니다. Working Set·Handle 같은 용어는 원래 이름 그대로 씁니다. 「자주 쓰는 질문」 버튼도 실제로 많이 묻는 질문으로 바꿨습니다.
